`.github/scripts/smoke_release_tree.py`'s `SmokeResult.ok` is `not self.errors and
all(r.returncode == 0 for r in self.runs)`, and `all()` over an empty list is `True`
in Python. If the release tree is ever missing `scripts/window-spread.py` (say, an
accidental deny-list addition in `.github/release-branch.json` denies `scripts/`) at
the same time `--validate` is `skip`, or `claude` is unavailable in `auto` mode,
`run_smoke` performs zero actual checks and `result.ok` is still `True` -- `report()`
prints `smoke: OK`, exit 0, the same receipt a genuinely passing run prints.

Found by `oss:auditor` during #12's self-review (Class A: absence the caller cannot
read). `tests/test_smoke_release_tree.py::test_no_script_is_a_note_not_a_failure`
encodes exactly this as intended behavior today (asserts `result.ok is True` for an
empty tree with `--validate skip`), so it is not an accident of this diff, just a
receipt that cannot distinguish "validated" from "validated nothing." Ranked
`misreports`, non-blocking (nothing is written or lost, only the report is wrong) --
logged here rather than fixed in #12 because changing `ok`'s semantics would also
mean deciding what `report()` should say instead (a new state, or an error?), which is
a design call past what #12 was briefed to make, and it would break the test above on
purpose, which deserves its own look rather than a drive-by edit.
