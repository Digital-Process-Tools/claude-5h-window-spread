`.oss/assemble_changelog.py`'s `REPO = Path(__file__).resolve().parents[2]` (around
line 57) resolves one directory too high for where this file actually lives. The
script sits at `<repo>/.oss/assemble_changelog.py` -- two path components below the
repo root (`.oss`, then the filename) -- so `.parents[1]` is the repo root and
`.parents[2]` is the repo's *parent* directory. Running the documented check command
with no flags,

    python3 .oss/assemble_changelog.py --check --check-links

fails with `cannot read <parent-of-repo>/CHANGELOG.md: [Errno 2] No such file or
directory`, from both `/Users/floriandavid/Documents/claude-5h-window-spread` (the
main clone) and `/Users/floriandavid/Documents/claude-5h-window-spread-wt/12` (a
worktree) -- so it is not a worktree artifact, it is wrong wherever the script is run
from, because the bug is in `__file__`-relative path math, not cwd.

Workaround used while writing #12's changelog fragment: pass the paths explicitly --
`python3 .oss/assemble_changelog.py --check --check-links --changelog CHANGELOG.md
--dir changelog.d` -- which resolves relative to cwd and works when run from the repo
root.

Separately, `.claude/jit-context/paths/01-oss/changelog-fragments.md`'s own "Check
before pushing" command names `scripts/assemble_changelog.py`, which does not exist in
this repo at all -- the real file is `.oss/assemble_changelog.py`. Confirmed by `ls`:
no `scripts/assemble_changelog.py` anywhere in the tree. So the documented check
command is wrong in two ways at once: the path named by the JIT doc doesn't exist, and
the file that does exist mis-derives its own repo root.

`.oss/` is owned by the oss plugin (replaced wholesale by `/oss:scaffold`, per
`.oss/README.md`), so this is not something to patch in this repository -- it needs
reporting upstream against the oss plugin/loop tooling itself, not fixed here.
